Create demo users

Give each person an email, a password and a role. Then download users.js and upload it to your GitHub repository, replacing the old one. Everything on this page runs on your own computer. Passwords are never sent anywhere.

Read this first. This is a gate for a demo, not real security. users.js is public on GitHub: anyone can read the names and the scrambled (hashed) passwords, and a determined person can get past the gate. Use throwaway passwords that you do not use anywhere else, and sample data only.

3. Add many users from a file

Download the template, fill it in with Excel (or any spreadsheet program), save it as CSV, and upload it here. You see every row checked before anything is added.

What to put in each column
EmailRequired. The person signs in with it. Not case sensitive.
NameShown in the app. If empty, the email is used.
RoleRequired. One of: . Or the name of a profile you created in the app (for example Finance).
ShippersRequired for a External Logistics Partner: the shippers they work for, separated by a bar or semicolon, for example Acme Exports Ltd | Beta Trading. They work like a Logistics Executive, only for those shippers' shipments.
CarrierRequired for a Carrier Partner, empty for everyone else. Known carriers: . It must match the carrier on the shipments.
WarehousesRequired for a Warehouse Team user. Separate several with a bar, for example RD - Fremont | RD - Germany. Known warehouses:
PasswordAt least 10 characters. Leave it empty and a strong password is generated for a new user, or the current password is kept for a user who is already in the list.
Show demo toolsYes or No. Tick Yes only for yourself. Empty means No (or unchanged for an existing user).

A user whose email is already in the list is updated. Up to 300 rows per file. Do not email the filled file: it can contain passwords.

5b. Shared data (Supabase)

Browsers cannot share data by themselves, so the app saves it in a small free online database. Follow these steps once.

  1. Go to supabase.com, sign up (free) and click New project. Choose any name and region and wait for it to finish.
  2. Open SQL Editor, click New query, paste the SQL below, and click Run.
  3. Open Project Settings, then API (or API Keys). Copy the Project URL and the anon public key (also called the publishable key). Never use the secret or service_role key.
